# نصب تنظیمات بات و فرم رسمی

این تغییر شامل بک‌اند، مهاجرت دیتابیس، پنل، سایت عمومی و بات است. فقط ری‌استارت
بات یا فقط کپی‌کردن خروجی پنل کافی نیست. اطلاعات واقعی حساب را بعد از نصب در پنل
وارد کنید؛ اطلاعات نمونهٔ PDF برای پرداخت نیست.

## نصب با بستهٔ آماده

در ترمینال **مک**:

```bash
scp /tmp/asa-bot-settings-update.tar.gz asauser@89.44.240.98:/home/asauser/
ssh asauser@89.44.240.98
```

سپس داخل **سرور**:

```bash
mkdir -p /home/asauser/asa-bot-settings-update
cd /home/asauser/asa-bot-settings-update
tar -xzf /home/asauser/asa-bot-settings-update.tar.gz
sudo python3 install.py
```

اگر دریافت پکیج‌های Python از PyPI با خطای اتصال مواجه شد، همان نصب را با میرور
HTTPS اجرا کنید:

```bash
sudo env ASA_PIP_INDEX_URL=https://mirror-pypi.runflare.com/simple python3 install.py
```

نصب‌کننده قبل از تغییر، از فایل‌ها، خروجی پنل و سایت و دیتابیس PostgreSQL در
`/var/backups/asa-bot-settings/` پشتیبان می‌گیرد. وب و بات را بازسازی می‌کند،
مهاجرت در راه‌اندازی وب اجرا می‌شود و سپس PDF و آماده‌شدن بات کنترل می‌شود.
توکن موجود، فایل `.env`، تنظیمات Nginx و SSL عوض نمی‌شوند. دیتابیس متوقف یا حذف
نمی‌شود. اگر نسخهٔ سرور از `docker-compose.bale.yml` استفاده کند، نصب‌کننده آن
را هم در فرمان‌های Compose لحاظ می‌کند.

## تنظیم و آزمایش

1. وارد `https://admin.asaeng.org` شوید و «تنظیمات بات» را باز کنید.
2. مبلغ را به **ریال**، نام صاحب حساب و کارت، حساب یا شبای معتبر وارد کنید.
3. «بررسی و ذخیره تغییرات» را بزنید؛ اطلاعات را بررسی و رمز حساب مدیر را تأیید کنید.
4. «مشاهده فرم با تنظیمات ذخیره‌شده» را باز کنید؛ مبلغ، مقصد و نام صاحب حساب را بخوانید.
5. در `https://ble.ir/AsaengBot` دستور `/start` بفرستید و «ثبت درخواست بازرسی» را بزنید.
6. PDF و متن پرداخت باید با تنظیمات ذخیره‌شده یکسان باشند.

تغییرات فقط برای درخواست جدید استفاده می‌شوند؛ پیام‌ها و PDFهایی که قبلاً برای
مشتری فرستاده شده‌اند، در بله به‌صورت خودکار عوض نمی‌شوند.

بعد از پنج تأیید رمز ناموفق، تغییرات حساس برای همان مدیر ۱۵ دقیقه قفل می‌شوند.
منشی یا کارشناس حتی با دسترسی امور مالی اجازهٔ تغییر مقصد پرداخت را ندارد.
سابقهٔ تغییرات در همان صفحه قابل مشاهده است. توکن بات و رمزها در پنل نمایش داده
نمی‌شوند. دسترسی مستقیم مدیر سرور یا دیتابیس همچنان باید محافظت شود.

## بررسی یا بازیابی در صورت خطا

اگر نصب موفق اعلام نشد، مسیر پشتیبان و خطای انتهای خروجی را نگه دارید. برای
دیدن وضعیت، در `/opt/asa` اجرا کنید:

```bash
sudo docker compose -f docker-compose.prod.yml -f docker-compose.bale.yml --profile bot ps
sudo docker compose -f docker-compose.prod.yml -f docker-compose.bale.yml --profile bot logs --tail=40 web bot
```

اگر فایل overlay وجود ندارد، گزینهٔ `-f docker-compose.bale.yml` را حذف کنید.
فایل پشتیبان `.env` را در چت یا Git قرار ندهید. پوشهٔ `files` در پشتیبان، نسخهٔ
قبلی فایل‌های موجود را نگه می‌دارد و خروجی‌های قبلی در `frontend/dist` و
`public-site/dist` هستند؛ پس از بازگرداندن فایل‌های موردنیاز، وب و بات باید
دوباره ساخته شوند. مهاجرت جدید فقط فیلد و جدول اضافه می‌کند؛ برای برگشت کد قبلی
لازم نیست دیتابیس را پاک کنید یا پشتیبان را روی داده‌های جدید بازگردانید.
