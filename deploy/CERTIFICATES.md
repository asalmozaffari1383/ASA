# گواهی بازرسی ایمنی

در پنل کارکنان، بخش «صدور گواهی‌نامه»، درخواست را انتخاب کنید. پیش از صدور می‌توان شماره، نوع تصرف، پیوست و متن توضیحات را وارد کرد. شماره خالی با کد رهگیری جایگزین می‌شود و پیوست خالی به صورت «ندارد» نمایش داده می‌شود.

خط اول توضیحات مقدمه گواهی است؛ هر خط غیرخالی بعدی یک بند از شرایط گواهی می‌شود. متن پیش‌فرض قابل ویرایش و بازگردانی است. پس از صدور، اطلاعات گواهی ذخیره و در این صفحه فقط خواندنی می‌شود. متن‌های طولانی به صفحات بعد ادامه پیدا می‌کنند؛ امضاها پس از آخرین بند قرار می‌گیرند.

سربرگ و اطلاعات تماس از نمونه ارائه‌شده استخراج شده‌اند. امضاها از تصویر امضای کارشناس گزارش و صادرکننده در پروفایل آن‌ها خوانده می‌شوند؛ امضای نمونه در خروجی کپی نمی‌شود. QR به صفحه پیگیری همان درخواست متصل است. گواهی‌های قبلاً صادرشده خودکار تغییر نمی‌کنند.

تصویر امضا مستقیماً از ذخیره‌ساز با دسترسی سرور خوانده و داخل PDF جاسازی می‌شود؛ بنابراین وابسته به عمومی بودن لینک S3 یا تاریخ انقضای لینک نیست. حاشیه خالی تصویر حذف و نسبت ابعاد حفظ می‌شود. کارشناس در سمت راست و صادرکننده در سمت چپ، بعد از توضیحات و بالای کادر اعتبار قرار می‌گیرند. اگر فایل امضای ثبت‌شده خراب، خالی یا در دسترس نباشد، صدور با پیام خطا متوقف می‌شود تا گواهی بدون امضای ثبت‌شده تولید نشود. برای کاربری که هنوز امضا ثبت نکرده، جای امضا خالی می‌ماند.

## اعمال روی VPS

پس از انتقال تغییرات به مخزن، با کاربر `asauser` روی سرور:

```bash
cd /opt/asa
git pull --ff-only
sudo docker compose -f docker-compose.prod.yml up -d --build web
sudo docker compose -f docker-compose.prod.yml exec web python manage.py migrate --noinput
cd frontend
npm ci
npm run build
```

سپس پنل را بازخوانی و با یک درخواست آزمایشی PDF را بررسی کنید. اگر پروژه روی سرور ابزار Node.js ندارد، خروجی build محلی `frontend/dist` باید با روش استقرار فعلی به `/opt/asa/frontend/dist` منتقل شود. از اطلاعات دیتابیس قبل از استقرار نسخه پشتیبان بگیرید.
